# yuki Translator — Studio UI・アプリ別音声取得版

Windows用の通話・ブラウザ・ゲーム向けローカル翻訳アプリです。日本語・韓国語・英語の認識、直接翻訳、ローカル読み上げ、最前面の透明字幕に対応します。

## 起動

最上位の **「翻訳アプリを起動」** をダブルクリックしてください。新版の本体は `内部ファイル/releases/studio-v6/YukiTranslator/YukiTranslator.exe` です。以前のアプリが起動中なら閉じてから起動し直してください。Pythonや追加音声のインストールは不要です。

配布時は `YukiTranslator` フォルダー全体をコピーします。exeだけを取り出すと動きません。モデル、関連ファイル、旧版はすべて「内部ファイル」に置いています。

## メイン画面

入力元と翻訳方向を選び、「翻訳開始」を押します。モデル・読み上げ方式・出力デバイスは「設定」にまとめました。

**音声読み上げ** と **字幕** は別々のスイッチで、翻訳中も切り替えられます。字幕OFFでは画面上の字幕を表示せず、音声OFFでは読み上げません。両方OFFでもアプリ内の翻訳ログは更新されます。字幕だけの場合は読み上げ出力デバイスがなくても開始できます。

## 取得するアプリ

Discordだけでなく、Chrome・Edge・Firefoxなどのブラウザ、ゲームや通話アプリを入力一覧から選択できます。先に対象アプリを起動し、「デバイス再取得」を押してください。ウィンドウを持たないVCプロセスなどは「設定」→「バックグラウンドのプロセスも一覧に表示」で探せます。

選択したプロセスとその子プロセスの再生音を取得します。ブラウザは同じプロセスツリーにある他タブの音声、ゲームはBGM・効果音も含まれます。VCの声だけを分離する機能ではありません。VCが別の独立したアプリで動いている場合は、そちらを選択してください。アプリ終了・再起動時は安全に停止し、勝手に他の音声へ切り替えません。

Chromeの別テストプロファイルで音声再生→アプリ別取得→韓国語認識→日本語翻訳の実機テストに合格しました。ゲーム個別の互換性、保護された音声、管理者権限やアンチチートによる制限のあるアプリまでは保証していません。

## 画面の表示言語

右上の **表示言語 / 화면 언어 / App language** で日本語・한국어・Englishを切り替えます。ボタン、モデルの説明、接続ガイド、状態表示も切り替わります。表示言語を変更しても、翻訳元・翻訳先は変わりません。

## モデル選択

「音声認識モデル」から選べます。両モデルを同梱済みです。

| 選択肢 | 用途 | 実行方式 |
|---|---|---|
| Qwen3-ASR 0.6B — 軽量 | 待ち時間や負荷を抑える標準モデル | CPU / int8 |
| Qwen3-ASR 1.7B — 少し重め | 大きめの認識モデルを試したい場合 | CPU / int8 |

今回追加したモデルは1.7Bです。4B級モデルは搭載していません。1.7Bは0.6Bよりメモリ使用量と処理時間が増えます。モデルは停止中に切り替えます。翻訳は共通のNLLB-200 600M int8で、英語を経由せず日本語と韓国語を直接翻訳します。

## Discordで相手の韓国語を聞く

1. Discordのデスクトップアプリを起動します。
2. 「音声入力」を **Discord** にします。見つからなければ「デバイス再取得」。
3. 対象言語は「自動判定」、翻訳先は「日本語」を選びます。
4. 読み上げ出力をヘッドホンなどに設定し、「翻訳開始」を押します。

Discord専用入力はDiscord本体と子プロセスの再生音だけを取得します。マイク・ゲーム・他アプリ・本アプリの読み上げは混ぜません。Discord内の動画や通知音は含まれます。Windowsビルド20348以降が必要で、ブラウザー版Discordは使用しているブラウザを選ぶことで取得できます（同じブラウザの他タブの音も含みます）。

入力メーターが動かなければ、通話参加・ミュート・相手の音量を確認してください。Discord再起動後は入力デバイスを再取得します。

## 日本語から韓国語の読み上げ

「設定」にある「読み上げ方式」は **ローカルAI（日・韓・英）** が標準です。Supertonic 3を同梱し、Windowsに韓国語のSAPI音声がなくても韓国語を読み上げます。従来の「Windows（ローカル）」設定は初回起動時にローカルAIへ移行します。インターネット接続は不要です。

1. 翻訳先を「韓国語」にします。
2. 「音声読み上げ」をONにし、音量を上げます。
3. 読み上げ出力を選びます。
4. **「読み上げテスト」** を押すと韓国語のテスト音声が流れます。

音量0〜100%を再生中にも変更できます。OFF・停止で再生を中断します。出力デバイスはWindowsの既定デバイスを最初に選び、以降は選択を保存します。

自分の日本語をDiscordの相手へ送る場合は、アプリの音声入力をマイク、対象言語を日本語、翻訳先を韓国語にします。[VB-CABLE](https://vb-audio.com/Cable/)などの仮想オーディオケーブルを別途導入し、アプリの読み上げ出力を `CABLE Input`、Discordの入力を `CABLE Output` にしてください。通常のヘッドホン出力を選ぶだけでは相手へは送られません。

オンライン読み上げも選択できます。この場合のみ翻訳済みテキストをMicrosoftの音声サービスへ送信し、ネット接続が必要です。オンラインへの自動切り替えは行いません。

## 映画風の透明字幕

**「字幕レイアウト」** タブで調整します。

- 背景、タイトルバー、枠は透明。黒い縁取りを付けた白文字だけを表示します。
- 表示する画面を選び、上下・中央・左右を組み合わせた9か所から配置できます。
- 画面のプレビュー内をクリックするとそこへ移動します。字幕の枠をドラッグして直感的に位置を調整でき、表示位置は実際の字幕と連動します。
- 「画面上で直接移動」をONにすると実際の字幕に移動用の枠が出ます。枠全体をつかんで移動できます。OFFに戻すと文字だけの透明字幕になり、クリックが背後のアプリへ通ります。
- 文字サイズ、不透明度、認識原文も表示するかを変更できます。
- 位置と表示設定は自動保存されます。字幕のON/OFFはメイン画面の「字幕」スイッチで切り替えます。OFF中もプレビューで位置を設定できます。

通常ウィンドウ・ボーダーレスゲーム向けです。排他的フルスクリーンでは最前面に出ない場合があります。画面を切断した場合は再起動し、使用できる画面を選んでください。

## 制約とプライバシー

発話を約0.8秒の無音または最長7秒で区切り、その後に認識・翻訳します。認識には音量補正とSilero VADを使用します。認識文の仮名・ハングルなどで言語を判定し、漢字だけの文や日韓混在など曖昧な場合は保留します。選択言語を認識モデルへ強制しないため、日本語を韓国語として無理に認識しません。翻訳先と同じ言語なら原文だけを表示します。

実際の訛り・同時発話・固有名詞などには誤認識や誤訳が残る場合があります。通常動作では録音を保存せず、認識・翻訳・ローカル読み上げを端末内で処理します。オンライン読み上げを選択した場合のみ訳文を送信します。会話履歴はメモリ内のみです。

設定・エラーログは `%LOCALAPPDATA%/yuki-Translator` に保存されます。ソース版は「内部ファイル」内に保存します。

## v6の検証

36件の回帰テスト、Chromeの音声取得と認識・翻訳、2つの別プロセスのテスト音を分離する実機テストに合格しています。対象アプリのPIDが再利用されても誤って別プロセスへ接続しないこと、字幕OFFのまま結果が到着しても再表示しないこと、音声出力がない字幕専用モードを確認しました。

## 検証と開発

両認識モデルで、日韓の合成音声6種類×通常・小音量＋雑音の12条件を検証し、空白・句読点を除いた内容は両方とも12/12一致しました。1.7Bで出力されることがある内部用言語タグは除外します。この小規模テストは、実際の友人との通話での精度やモデル間の一般的な優劣を保証するものではありません。

テスト結果は `tests/accuracy-qwen3-asr.json`、`tests/accuracy-qwen3-asr-1.7b.json`、ローカル読み上げの実機出力確認は `tests/speech-output-v5.json` を参照してください。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tests/check_accuracy.py
.\.venv\Scripts\python.exe tests/check_accuracy.py 'Qwen3-ASR 1.7B int8'
.\.venv\Scripts\python.exe tests/check_speech_output.py
```

最後の音声テストは短い韓国語音声を実際に再生します。モデル・DLL・透明字幕・表示言語の統合診断は `YukiTranslator.exe --self-test <結果JSONの絶対パス>` で行えます。診断は通常の設定を上書きせず、読み上げ音声の生成まで確認します。

開発環境はPython 3.11。`setup.ps1`で標準モデルと依存関係を導入します。ソース環境で1.7Bを追加する場合は画面で選択後「モデル導入」。両モデルの準備後に `build.ps1` でWindowsアプリを再作成できます。
